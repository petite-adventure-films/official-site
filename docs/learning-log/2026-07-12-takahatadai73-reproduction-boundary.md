# 2026-07-12: 高幡台73号棟ページの復刻UIとテスト境界

## テーマ

`takahatadai73` 復刻ページで、ページ固有の静的コンテンツと、他ページでも使うUI部品の責務を切り分ける。

あわせて、元Nuxt版のUIをAstro版でどこまで再現するかを確認する。

## Pre説明

`index.astro` は、このURLで何を表示するかを組み立てる責務を持つ。

`constants` は、ページ表示に使う静的データを持つ。

`Layout` は、サイト共通のHTML土台、meta、ヘッダー、ナビ、wrapperを提供する。今回の `transparentWrapper` は、このページ固有の背景画像を活かすために共通Layoutへ追加した分岐。

画像読み込みは、現時点ではこのページ固有の事情が強いため `index.astro` 内で扱う。

## 今日やったこと

- `takahatadai73` ページに、元Nuxt版の年表データと解体ギャラリーデータを追加した。
- 年表内で参照する資料ファイルと、解体ギャラリー画像をAstro側へ移した。
- KVの建物画像を、元Nuxt版と同じ `sticky bottom-0 -z-10` の見え方へ戻した。
- timelineの月ボタン左右に出る三角を、月数字ではなく丸ボタンを基準に配置するよう修正した。
- 住民紹介を、単純な2カラムgridではなく `columns` と `break-inside-avoid` でmasonry風に表示するよう修正した。
- films詳細ページのcredit欄でも `columns + break-inside-avoid` を試したが、filmsでは厳密なmasonryのほうがよいと判断し、ユーザー側で元のmasonry実装へ戻した。

## 実装メモ

復刻ページでは、元ページのUIや操作感を仕様として扱う。

今回、ギャラリーを一度 `<details>` 一覧として実装したが、これは「写真が見られる」だけで、元のカレンダー型ギャラリー体験の再現にはなっていなかった。

今後は、元UIと違う形にする場合は、実装前に「完全再現するか、近似でよいか」を確認する。

## テスト方針の見直し

当初は、このページが特殊な固定ページなので、自動テストは不要と考えた。

ただし、作業中に以下の認識へ変わった。

- `takahatadai73` ページ本文そのものは固定コンテンツなので、`build` と目視確認が中心でよい。
- `Layout` の `transparentWrapper` は共通部品へ追加した分岐なので、将来的にはテスト対象になりうる。
- `Modal` と `Gallery` はこのページ専用ではなく、他ページでも使う汎用UIとして扱うべき。
- そのため、`Modal` と `Gallery` は明日以降、責務・API・テスト方針を決めてから一つずつ実装する。

## 学んだこと

テスト対象は「複雑そうな場所」ではなく、「変更の影響範囲が広い場所」を優先する。

また、復刻ページでは「データを表示すること」と「元の体験を再現すること」は違う。

ページ固有の静的コンテンツはテストしすぎない。一方で、共通化するUI部品は、使い回される責務を持つのでテストで守る。

## テスト

`pnpm build` は成功した。

ローカルのデフォルトNodeは18系だが、Astroは Node `>=22.12.0` を要求するため、Node 22.14.0 でビルドした。

WordPress API取得を含むため、ビルド確認にはネットワーク許可が必要だった。

## 今日の結論

`takahatadai73` は復刻ページなので、元Nuxt版のUIを仕様として扱う。

ページ固有の本文や静的データは、無理に細かくコンポーネント化しない。

ただし、`Modal` と `Gallery` はこのページだけの問題ではなく、今後の共通UIとして設計・テストする。
