# イベント固有のデータ設計

対象 #392 / #396。共通の識別・保存・複製・履歴・復元は [CMS共通データ設計](../002-cms-foundation/data-model.md) を参照する。イベントは `type=event` として登録する。

## payload

タイトル、開催状態（通常・延期・中止）、開始日・終了日、開催時間の案内、開催形式（会場・オンライン・併催の提案）、会場名、住所、地図URL、公開用参加案内URL、アクセス、料金、主催者・問い合わせ、備考、映画タグID配列、イベントタグID配列。

単日では終了日を省略。日付は年を含むYYYY-MM-DD文字列、公開表示の日付基準はAsia/Tokyoの提案。シリーズの各回は独立したContentDraft（type=event）。一般向けに出せない接続用パスワード等を入力する専用項目は設けない。

入力欄の空欄と途中入力を保存できる下書き契約を新設する。既存event/v1の必須title・slug・開始日・会場に合わせて無理にダミー値を入れない。公開用データへの変換は別の検証で行う。

## 検証

- 下書きでは文字列型、列挙値、配列、サイズ、未知フィールド、URLの安全性を検証。タイトル・日付・会場の空欄は許可する案。
- 日付の不成立・終了日逆転は入力を保持して問題を表示する。プレビューは不正値を正式な日付として解釈しない。
- 1リクエスト256KiB、タイトル200文字、説明欄各20,000文字を上限案とする。超過時は413/422で保存を拒否し、入力を画面に残す。
- 新規入力の説明欄はプレーンテキストと改行、URLリンクを第一案とする。既存HTMLの無損失編集は#334/#391と照合し、移行データをこの形式で上書きしない。
- タグは任意・複数。参照先不明なら問題を返し、勝手にタグを落とさない。
