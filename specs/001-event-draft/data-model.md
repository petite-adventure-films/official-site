# イベント固有のデータ設計

対象 #392 / #396。共通の識別・保存・複製・履歴・復元は [CMS共通データ設計](../002-cms-foundation/data-model.md) を参照する。イベントは `type=event` として登録する。

## payload

タイトル、開催状態（通常・延期・中止）、開始日・終了日、複数日設定のオン／オフ、開催時間の案内、開催形式（オフライン／オンラインの複数選択。両方選択で併催。不明は単独選択）、会場名、住所、地図URL、アクセス、開催場所の備考（参加方法・URLを含む）、料金、主催者・問い合わせ、イベント全体の備考、映画タグID配列、イベントタグID配列。

単日では終了日をプレビュー・公開用データから除外するが、下書きの終了日入力は保持する。複数日設定は終了日の有無から推測せず、独立した状態として保存する。成立した日付は年を含むYYYY-MM-DD文字列で扱うが、下書きでは空欄・途中入力・不正値も入力文字列のまま保持する。公開表示の日付基準はAsia/Tokyoの提案。シリーズの各回は独立したContentDraft（type=event）。一般向けに出せない接続用パスワード等を入力する専用項目は設けない。

入力欄の空欄と途中入力を保存できる下書き契約を新設する。既存event/v1の必須title・slug・開始日・会場に合わせて無理にダミー値を入れない。公開用データへの変換は別の検証で行う。

非表示項目の値も下書きpayloadに保持する。複数日をオフにした終了日、オンラインのみ、または未選択にした会場名・住所・地図URL・アクセスは、保存・再取得後も保持し、再び有効にすると再表示する。プレビュー・公開用データへの変換では設定が有効な項目だけを使用し、非表示の値を含めない。公開可否の検証でも、非表示項目の入力不備だけで公開を止めない。保存形式・容量の制限は非表示値を含む下書き全体に適用する。

## 検証

- 開催形式は下書きでは空配列を許可し、自動保存・保存ボタン・再編集で未選択状態を保持する。公開時はオフライン／オンラインの少なくとも1つ、または不明の単独選択を必須とする。不明は会場情報を保持し、未選択と区別する。未選択を自動でオフラインへ補正しない。

- 下書きでは保存可能なデータ形式（文字列型・列挙値・配列・未知フィールドなど）とサイズを検証する。タイトル・日付・会場の空欄や、入力内容の不正だけを理由に保存を拒否しない。自動保存と保存ボタンで同じ契約を使う。URLも入力文字列として保持し、安全性の検証はリンクとして表示・公開する際に行う。
- 日付の途中入力・不成立・終了日逆転は入力文字列をそのまま永続保存し、問題を表示する。再編集時も空欄への変換や自動補正をしない。プレビューは不正値を正式な日付として解釈しない。公開時は別の検証で不正な内容の公開を止め、現在公開中の内容を維持する。
- 1リクエスト256KiB、タイトル200文字、その他の文字列各20,000文字を上限とする。保存済み公開スナップショット234件ではタイトル最大72文字、既存の説明欄最大648文字だったため、入力の余裕を確保しつつ要求容量を制限する。文字列上限はUnicodeコードポイント、要求容量はUTF-8バイト数で判定する。超過時は413/422で保存を拒否し、入力を画面に残す。
- 新規入力の説明欄はプレーンテキスト・改行・URLリンクを扱う。文字列と改行を保存・再取得時に保持する。太字・見出し・画像などの装飾機能は今回の説明欄に含めず、本文エディタ #334 の範囲で扱う。表示時は文字列をエスケープし、http/httpsのURLだけをリンクとして扱う。HTMLやMarkdownを装飾として解釈しない。旧HTMLの扱いは[#491の変換仕様](../011-wordpress-conversion/spec.md)に従い、リンク付き項目を文字列で上書きしない。
- タグは任意・複数。参照先不明なら問題を返し、勝手にタグを落とさない。


## 実装フィールド

正確な型と上限は `packages/content-schema/schemas/content/event-draft.schema.json` を正本とする。`payloadSchemaVersion` は `event-draft/v1`。

- 文字列: `title`, `startDate`, `endDate`, `venue`, `address`, `mapUrl`。
- `timeDescription` / `access` / `venueNotes` / `fee` / `organizer` / `notes`: 文字列、または`event-text/v1`に適合するschemaVersion:2のテキスト専用JSON。既存文字列はHTMLとして解釈しない。書式付き値は段落・改行・限定した文字装飾と安全なリンクを保持し、画像・動画・asset参照を含めない。
- `multiDay`: boolean。`formats`: offline/onlineの重複しない配列、またはunknownだけの配列。`status`: normal/postponed/cancelled。
- `filmTagIds` / `eventTagIds`: 重複なしの文字列ID配列。各最大100件。タグはD1の種別＋IDで参照を検証する。
- 初期タグ一覧はGit管理されている `astro/data/wordpress-export.json` のイベントに現れるtaxonomyから取り込み、元のterm_idを文字列として保持する。`0002_tags.sql` はタグのみを登録し、既存記事やHTMLを下書きへ移行しない。タグ管理画面は今回設けない。

## slug（下書きの追加項目）

`slug?: string` をevent-draft/v1に後方互換の任意項目として追加する。未指定は記事IDを利用する意味で、保存時にタイトルから生成しない。明示的な空文字は入力途中として保存し、公開時は拒否する。下書き文字数上限は他の自由入力と同じ20000文字。画面では公開向けの200文字以内・パス区切りなどの不正・予約語archiveを案内するが、下書き保存は止めない。公開時の一意性・既存URL保護は公開処理側で検証する。複製ではslugを除いてコピーし、複製先IDを初期値にする。

## 公開候補データの生成（配信前）

`cms/worker/event-publication.ts` の `prepareEventPublication` が保存形式を確認し、項目ごとの公開要件を検証する。成功は `{ok: true, payload}`、失敗は `{ok: false, issues: [{field, code, message}]}`。失敗時に部分的なpayloadを返さない。関数は下書きやDBを変更せず、公開状態・履歴・配信要求を作らない。

形式は `packages/content-schema/schemas/content/event-publication.schema.json`、識別子は `event-publication/v1`。既存rich text向けevent/v1とは別契約で、既存スキーマ・公開WordPressデータを変更しない。現在は候補データの生成までで、汎用content envelopeやAstroへの接続は後続作業。

公開候補にはtype・payloadSchemaVersion・title・slug・startDate・formats・status・文章項目・タグID配列を明示的に含める。複数日のときだけendDate、オフラインを含むとき、または不明のときにvenue/address/mapUrl/accessを含める。会場名必須はオフラインの場合だけ。multiDayや非表示値、操作者などの管理情報は渡さない。配列も新しく作り、候補の編集が元の下書きへ影響しない。

日付は区切りを統一したYYYY/MM/DDまたはYYYY-MM-DDを受け、実在日を検証してYYYY-MM-DDへ変換する。混在区切り・年0000・時刻付き入力・不成立日・終了日逆転は拒否する。タイムゾーンによる日ずれを起こさない暦日として扱い、フォームの日付案内も同じ関数を使う。

空白だけのタイトル・会場名は必須不足。地図URLは絶対http/https、ホストあり、資格情報なしとし、空白・制御文字・バックスラッシュを拒否する。空欄の地図URLは許可する。slugは未指定時のみ記事IDを使い、不正文字や不正Unicodeは問題として返す。画面と公開候補のslug形式検証を共有する。

タグは呼出元が種別別の有効ID集合を渡して照合する。呼出元は公開要求時に現在のDBから取得する必要がある。slugの一意性・既存URL予約・タグ変更との競合を含む公開確定処理は未接続であり、`ok: true` を公開成功やURL取得済みと解釈しない。

文章は文字列・改行、または検証済みのテキスト専用JSONをそのまま保持する。この処理でHTMLをレンダリングしたりエスケープ済みHTMLへ変換したりしない。後続の公開レンダラーで文字列としてエスケープし、安全なリンクだけを組み立てる必要がある。
