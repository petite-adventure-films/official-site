# 実装後の確認手順案

対象 #392。[CMS共通機能](../002-cms-foundation/spec.md)をイベントで検証する。編集画面・保存API・一覧を接続済み。自動保存と手動保存、開き直しを検証済み。以下の検証シナリオ全体は未完了。

## 準備

Node 24、pnpm 10.28.2、Chromium。`cms/.env.example` を参照する。ローカル開発はクラウドの認証情報を必要としない。テスト用データのみを用い、公開サイト・本番DBを変更しない。

実行コマンド: `pnpm --dir cms install --frozen-lockfile`、`pnpm --dir cms run db:migrate:local`、`pnpm --dir cms run dev`、`pnpm --dir cms test`、`pnpm --dir cms run test:e2e`。共有表示の変更時は `pnpm --dir astro run test:e2e` も実行する。

`dev` はUIを `http://127.0.0.1:5174`、APIを `http://127.0.0.1:8787` で起動する。UIからは同一オリジンの `/api` をプロキシする。`/cms/events` で一覧、`/cms/events/new` で新規作成を開ける。ローカル専用エントリーは開発用ユーザーを使う。本番エントリーはJWT認証を必須とし、開発用エントリーをimportしない。ローカルDBは `cms/.wrangler/`。Vitestはテストごとのメモリー内DB、Playwrightは実行ごとの一時ディレクトリへDBを分離する。`dev` は起動前にローカルマイグレーションを適用する。本番設定にはローカルDBのIDや認証バイパスを含めない。

確認結果は [verification.md](verification.md) を参照。

## 検証シナリオ

- 作成日時と更新日時の順が異なる記事で、一覧が作成日時の新しい順・1ページ20件になることを確認する。キーワードの入力中やIME変換確定のEnterでは検索せず、入力確定後のEnterで検索する。後続ページから検索・空欄Enterによる解除を行うと1ページ目へ戻り、検索結果と全件一覧で並び順・件数・ページ送りが一致することを確認する。

- 一覧を1440pxから段階的に狭め、タイトル列が縮み、長いタイトルが1行の「…」表示になることを確認する。全文は保存内容とリンクのアクセシブルな名前に保持する。一覧の最小幅以下では見出しと行が一緒に横スクロールし、タグ・公開状態へ到達できること、検索・新規作成・ページ送りとページ全体は横にはみ出さないことを確認する。キーボード操作と拡大表示も検証する。

- キーワードがタイトル・本文・会場・備考にある記事を検索でき、タグ名だけに一致する記事はキーワードでは検索されないことを確認する。タグは列見出し付きで一覧に表示され、タグによる絞り込み操作がないことを確認する。件数・ページ送りはキーワードの検索結果に一致することを確認する。

- 新規作成時はオフラインが選択済みで、両方を解除した下書きは自動保存・保存ボタンの両方で保存できることを確認する。再編集時も未選択を維持し、公開時は選択必須の問題を表示して公開を止める。オフラインのみ・オンラインのみ・両方は開催形式の選択条件を満たすことを確認する。

- 説明欄に文章・複数行の改行・http/httpsのURLを入力して保存・再編集し、内容が一致することを確認する。プレビューで改行とリンクが表示され、HTMLやMarkdownを装飾として解釈しないこと、http/https以外を実行可能なリンクにしないことを確認する。

- 終了日と会場情報を入力し、複数日をオフ・オフラインを解除して保存する。再編集後も非表示状態と値を保持し、設定を戻すと元の値が表示されることを確認する。非表示中の値はプレビュー・公開用データに含まれず、その不正値だけで公開が妨げられないことも確認する。開催場所の備考は常時表示のままとする。

- 空欄、途中入力の日付（例：`2026/1`）、存在しない日付、終了日が開始日より前の内容を、自動保存・保存ボタンの両方で保存して再取得する。入力文字列が変わらず、項目の問題表示と保存成功が両立することを確認する。
- 不正値をプレビューが勝手に補正しないこと、公開検証で拒否され現在の公開内容が変わらないことを確認する。公開処理が未実装なら公開検証を確認済みにしない。
- 保存形式違反・容量超過では保存失敗となり、画面内の入力と直前の保存内容を保持することを確認する。


1. 許可された2人は同じ編集操作ができる。未認証・未許可ユーザーは一覧・API・プレビューへ到達できない。改ざんJWT、誤audience、失効、既定Workerホストからの迂回も拒否する。
2. タイトル・開催日が途中の下書きを保存し、再読込後に内容を照合する。任意タグの未選択・複数選択を確認。
3. 入力停止後の自動保存と手動保存、応答遅延中の追加入力、失敗・再試行、再送を確認。下書きの重複作成と誤った保存済み表示がない。
4. 二つの画面で同じversionを編集して競合を発生させる。一方が黙って上書きされない。
5. 保存前の変更をプレビューし、編集へ戻る。保存失敗中でも内容が表示され、保存成功とは表示されない。
6. 複製して日付・会場を変更。元の内容は不変、新しい下書きは非公開。再送しても複製が増えない。
7. 年越しの連続期間、別告知によるシリーズ、オンライン、延期・中止を確認。公開一覧の年越しと日付更新は#394の検証にも接続する。
8. キーボード・360px・200%/400%拡大・読み上げで主経路を手動確認。自動アクセシビリティ検査を併用し、WCAG達成基準ごとに結果と未確認を記録。
9. JSON/SQLエクスポートから別の空DBへ復元し、件数・識別子・保存内容を照合。元DBを書き換えずに検証する。
10. 履歴から過去の内容を復元し、新しいversionになること、復元前の版が残ること、公開されないことを確認する。未保存入力・保存失敗・同時更新・再送・他の告知の履歴指定でも、消失や誤復元がない。
11. 公開ビルド・静的成果物・ログに下書きや認証情報が混入しないことを確認。

本番利用前に、認証アカウントの復旧、バックアップ保存先・保持期間・失敗検知を運用手順として確認する。

複製は編集画面右側のタグの下から実行する。入力直後に複製しても最新の入力が保存され、新しいIDの下書きへ移ること、複製先の編集が元記事に影響しないことを確認する。通信失敗時の再試行は同じ複製を返す。

公開接続の確認項目は [公開接続の設計案](../002-cms-foundation/contracts/publication.md#確認シナリオ) を参照する。実際の配信先・認証は未設定で、この設計作業では公開テストを行っていない。
