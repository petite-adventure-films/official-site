# Feature Specification: CMSの認証・編集・保存基盤

**Feature Branch**: `feat/issue-392-event-draft`
**Created**: 2026-11-08
**Status**: 主要要件確認済み、詳細設計レビュー中
**Input**: イベントで最初に利用するCMS共通機能を、Spec Kitの機能単位として整理する。
**対象Issue**: #392。関連 #333（基本操作）、#396（データ）、#397（保存）。

## User Scenarios & Testing

### User Story 1 - 許可された利用者が編集する (Priority: P1)

監督と開発担当者がそれぞれログインし、同じ権限でコンテンツを編集する。

**Independent Test**: 2人のログインと、未認証・未許可利用者のアクセス拒否を確認する。
**Acceptance Scenarios**: 許可された2人は一覧・編集へ進める。未許可利用者は下書きやプレビューの内容を取得・変更できない。

### User Story 2 - 作成・保存・再編集・複製する (Priority: P1)

新しいコンテンツを作成して途中保存し、後から入力を再開する。複製は入力内容をそのまま引き継いだ独立した下書きを作る。

**Independent Test**: 作成→保存→再表示→複製→変更を一巡する。
**Acceptance Scenarios**: 保存した全項目が保持される。複製した日時や状態も元と一致し、編集後も元のコンテンツは変わらない。保存・複製では公開されない。

### User Story 3 - 保存状態を把握し内容を確認・復元する (Priority: P1)

利用者は未保存・保存中・成功・失敗を区別し、現在の入力をプレビューする。保存履歴から内容を確認し、過去の内容へ戻せる。

**Independent Test**: 保存失敗・追加入力・同時編集を再現し、未保存プレビューと履歴復元を確認する。
**Acceptance Scenarios**: 保存失敗時も入力を保持し、成功と誤表示しない。選んだ履歴は新しい下書き版として保存され、復元前の版も残る。

### Edge Cases

認証失効、通信断、保存応答の喪失、同時編集、空欄、未保存入力のある複製・復元を検証する。再送で重複作成せず、他の更新を黙って上書きしない。

## Requirements

### Functional Requirements

- **CMS-001**: 2人の個別アカウント・同じ操作権限を提供する。
- **CMS-002**: 新規作成、一覧から開く、下書き保存、再編集、複製を共通操作として提供する。
- **CMS-003**: 入力内容の複製と、識別子・公開状態・履歴の新規発行を区別する。
- **CMS-004**: 保存状態と開催など種別固有の状態を区別し、失敗時は入力を保持する。
- **CMS-005**: 未保存分を含む現在の入力をプレビューできる。プレビューの表示成功を保存成功と扱わない。
- **CMS-006**: 保存履歴を閲覧し、選択した版を新しい下書き版へ復元できる。スナップショット方式の負担・保持方針を設計で確認する。
- **CMS-007**: 保存・複製・復元から公開を実行しない。
- **CMS-008**: 共通品質基準に従い、キーボード操作、状態・エラーの認識、拡大表示を含めて評価する。

### Key Entities

利用者、コンテンツ下書き、保存履歴、コンテンツ種別。詳細は [データ設計](data-model.md) を参照する。

## Success Criteria

- 許可された2人が全共通操作を完遂し、未許可のアクセスは拒否される。
- 作成・保存・再表示で入力が一致し、複製と復元の独立性・非公開状態が保たれる。
- 失敗・遅延・再送・競合の各ケースで、入力消失や誤った保存成功を起こさない。
- 共通品質基準の確認結果と未確認事項を記録する。

## Assumptions

最初の対応種別は [イベント](../001-event-draft/spec.md)。他の種別は個別要件の確認後に追加する。種別の入力項目・検証・表示内容は種別側の仕様を参照する。保存履歴の保持方針、画面案、導入時の費用・ホスト名・復旧手段はレビュー事項。
