# イベント以外のコンテンツスキーマの棚卸し

対象 #410（親 #396）。CMS編集範囲の正本は [#407 の仕様](../003-cms-content-scope/spec.md)。

## CMS対象と既存定義

`packages/content-schema/schemas/content/` と同パッケージの `samples/content/` を、`astro/data/wordpress-export.json` の公開データ（2026-08-10時点）に照合した。以下のv1スキーマを採用済みのCMS入力仕様とは扱わない。

| 対象 | 既存スキーマ・サンプル | 旧データとの差分と要決定事項 |
| --- | --- | --- |
| ブログ（310件、#418） | `blog`。リッチテキスト本文、カテゴリ、作品ID、カバー画像、推薦・ワークショップ報告フラグ | 旧 `name` を使うURL、カテゴリ・一般タグ・映画タグ、サムネイルを対応づける。必須カテゴリと報告フラグの欠損時の扱い・編集方法を決める |
| お知らせ（245件、#419） | `news`。タイトルとリッチテキスト本文 | 現行の公開・更新日時、旧ID、一覧でのリンク先を維持する方法を決める。個別slugが必要かは公開側の導線と合わせて判断する |
| メディア掲載（22件、#420） | `press-coverage`。出典・号、抜粋、添付ID、動画、作品ID | 旧データのPDF URL、動画、掲載本文を対応づける。必須の出典名・種別・要約を旧データで満たせるか確認し、欠損の扱いを決める |
| チャンネル（21件、#421） | `video`。説明、YouTube、制作年・国・秒数、作品ID | 旧YouTube ID、制作年・国、上映時間を対応づける。動画IDや制作情報がない既存記事の取り扱いを決める。チャンネルと汎用動画の範囲も確認する |

## 共通の確認と後続Issue

- **本文・リンク** — 旧本文からリンク、画像、PDF、動画を抽出し、既存リッチテキストで表現できる例と変換できない例を確認する。CMSで編集できる表現と移行時に残す表現は #334・#391 で合意する。今のv1に合わせて本文を削らない。
- **画像・PDF・動画** — 既存の画像ノードとYouTube参照に加え、本文中のPDFや外部リンクの扱い、直リンクを添付IDに置き換える条件を #395・#391 で決める。
- **作品との関連・旧データ** — 作品はコード管理で、CMS側は参照する。旧映画タグと作品IDの対応、複数関連、対応先がないタグを #391 で確認する。旧IDとURLの保持、欠損フィールドの変換規則も移行側で記録する。
- **作品・商品とその他の定義** — `film`、`product`、`faq`、`category`、`event-kind` にもスキーマとサンプルがある。作品紹介はコード管理。商品は現行データが `astro/src/constants/products_dvd.ts` にあり、運用と必要項目は #376 で確認する。分類データの編集範囲は各記事種別の作業に含める。
- **実装・検証** — #418〜#421で、各種別の下書き・公開契約、通常例、旧データの欠損例を個別に揃える。共通操作は #333、本文エディタは #334 を参照する。#391 では変換後のデータと公開URL・添付参照を検証する。
