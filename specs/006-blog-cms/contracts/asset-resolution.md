# ブログ添付のURL・実ファイル・ID対応（設計検証）

対象 #418 / #334、添付登録 #395、移行 #391。既存の2026-08-10公開スナップショットと、2026-08-11のメディア台帳を照合した。R2への書込み、asset ID登録、本文URLの置換は行っていない。

## 参照の分類

| 対象 | 結果 |
| --- | --- |
| 本文画像src | 5,923箇所（自サイト5,922、外部GIF1） |
| 画像へのクリック先href | 179箇所。画像srcだけでなくクリック先も移行対象として追跡 |
| PDFリンク | 5箇所・4URL、すべて外部サイト。自サイトPDF添付はこのブログ本文にはない |
| 画像/PDFの異なるURL | 6,038件。スキーム・query・fragment差は消さず保持 |
| 自サイトの異なるURL | 6,033件、既存台帳の5,895パスへ対応候補あり。台帳未照合0件 |

パス一致は同一バイト・同一assetの証明ではない。既存台帳の `wordpress/<path>` は移行候補キーであり、asset/v1が要求する `originals/<hash-prefix>/<hash>.<ext>` の保存済みオブジェクトとは別。http/https、元画像/縮小版、異なるファイル名を自動的に同一assetへまとめない。

自サイト判定は既知ホスト完全一致＋uploadsパス＋http/httpsで行う。ホスト偽装、資格情報付き、別ホスト、異常ポートを自サイトとして扱わない。URLの所有区分は実ファイル確認とは独立する。

## PDFと外部画像の方針案

ブログのPDF5箇所はgender.go.jp、utagoe.gr.jp、iwanami.co.jp、city.tomakomai.hokkaido.jpの資料である。外部資料は元URLの通常linkとして保持し、自サイトへ無断で複製・asset登録しない。末尾拡張子だけで全PDFをunresolvedAssetLinkにする案を修正した。外部URLの到達性は別途検証が必要。

自サイトのPDF・画像へのhrefは `assetLink` / `unresolvedAssetLink` とし、assetKind（image/document）を持つ。本文画像のsrcが解決しても、クリック先が旧WordPress依存のまま残らないよう両方を照合する。今回はブログ内の自サイトPDFは0だが、他コンテンツと共有する契約としてPDF正例を合成fixtureで検証した。

4772の外部GIFは `ssl.gstatic.com/.../cleardot.gif`。コピー元メールの補助画像と思われるが、解釈だけで削除せず原文参照を保持し、外部画像の取り込み/除去方針を別途確認する。

| 4641 | 4 | 4件が取得可能 |

| 7277 | 1 | 候補なし。WordPressメディア原本/バックアップ等の確認が必要 |

通常画像1点と復旧候補1点、計2点を取得して画像デコード・実寸・byte数・SHA-256・ローカル再読出し一致を確認した。保存先は `/tmp/paf-verified-media/`、移行先キーは提案値のみ。全5,895候補のダウンロードは未実施。

[probe-result.json](../verification/asset-mapping/probe-result.json) に現在のHTTP結果と取得証拠を記録。欠損候補、URL/記事の対応と元台帳の照合は [inventory-result.json](../verification/asset-mapping/inventory-result.json) を参照。

## asset IDを発行できる条件

1. 原本URL・記事・用途（img src / image href / PDF href）を台帳へ固定する。
2. GETで取得した実体を検証し、MIME・SHA-256・byte数・画像実寸を記録する。HEAD成功やファイル名一致だけでは次へ進めない。
3. 不変asset IDを移行/登録台帳に永続化し、再実行でも同じ対応を再利用する。未取得URLに仮assetIdを与えない。同じhashの再利用と、表示寸法/alt等の記事固有情報を区別する。
4. R2へ保存し、保存済みオブジェクトとhash等の整合を確認してasset/v1レコードを登録する。ファイルが存在しないstorageKeyだけを登録しない。
5. URL別の対応を解決し、旧URLの到達経路・画像src/クリック先/PDFリンクを照合する。復旧候補は承認された対応として記録してから置換する。
6. 記事の本文・添付・URL・公開日等を照合し、本文契約の公開ゲートを通す。

実IDの発行・R2保管・所属/種別確認は正式サーバー処理へ接続する。本検証ではIDを発行しておらず、byte確認済みの代表画像も公開可能assetへ昇格していない。

## 保存契約への反映

外部PDFを通常リンクへ戻し、自サイト画像へのリンクをassetKind:imageの未解決参照として追跡した。310件の候補schema検証・逆変換は引き続き成功。実画像参照が未解決な252記事を公開停止する。本文単体の公開AST条件を満たす58記事も、サイト全体の公開準備完了ではない。

再現手順と検証範囲は [asset-mapping/README.md](../verification/asset-mapping/README.md) を参照。次の作業は全対象ファイル取得の実行計画、欠損8件の原本/復旧判断、R2/asset登録経路とURL台帳の永続化である。
