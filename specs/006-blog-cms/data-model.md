# ブログのデータ設計案

対象 #418。本文の形式・原本保全・確認待ち記事・動画の案は[本文契約](contracts/body.md)を参照。公開形式の最終化はplan.mdのゲートに従う。[編集本文・原本保全・公開ASTの境界](contracts/body-storage.md)と候補schemaを追加して設計検証済み。

## 下書き

共通エンベロープ（id/type/version/payloadSchemaVersion/payload/作成・編集時刻と操作者）を使う。typeはblog、保存schemaはblog-draft/v1を提案。idは不変UUID、versionは保存ごとに増加。

| payload | 下書き | 公開時・移行時 |
| --- | --- | --- |
| title | 空文字を保存可 | 空白だけでないタイトルを必須とする案 |
| slug | 未指定は記事ID。途中入力も保持 | /{slug}/、形式と所有権を検査。タイトル変更では変えない |
| body | rich-text/v2案。空の編集内容を保存可。移行確認待ちはサーバー管理の原本参照を保持 | 本文契約のノード・参照・内容あり判定を検証。未対応本文を落として公開しない |
| categoryId | 未選択はnullの案 | 既存カテゴリ1件必須、未知IDで公開不可 |
| filmTagIds / eventTagIds | 配列、初期値空 | 存在確認、映画タグ→作品IDの対応を確定 |
| isRecommended / isWorkshopReport | 独立boolean、初期値falseの案 | 旧おすすめと一般タグ5026の分類から引き継ぐ |

一般タグ・サムネイルの編集項目は追加しない。原本や旧一般タグは移行の保全データに残す。欠損カテゴリ・未対応本文を初期値で埋めて移行成功にしない。

## 分類と移行参照

カテゴリは旧ID・名称と新IDの一意な対応を持つ読み取り専用集合を提案。移行で照合した台帳から供給し、CMSの作成APIは設けない。映画/イベントタグは既存取得経路を使う。filmIdsとfilmTagIdsを同一と仮定せず、未対応を検出して公開を止める。

`source-reference.schema.json` のsourceType/sourceId/sourceUrl/targetIdを起点に旧WP IDとCMS IDを結ぶ。原本・取得時点は#391で保持する。これらのD1永続化が実装済みとは扱わない。

## 日時

- 元の記事公開日時、公開版更新日時、CMS作成/最終編集日時、履歴の公開操作日時を区別する。
- 旧公開日は移行値を再公開後も保持。新規は初回配信確定日時を使う案。複製には元公開日・URL・公開状態を引き継がない。
- 公開版更新日時は配信確定時に更新し、下書き保存では変えない。移行直後は元更新日時を保持する案。
- 日時入力欄は設けない。作成/最終編集日時は既存の公開管理欄。保存はタイムゾーン付き、表示はAsia/Tokyoで照合する。

## 公開・履歴・URL

保存済み版から候補を固定し、配信確認後に公開ポインタと履歴を更新。現行ready/delivering/unknown/failed/succeeded/noop、下書きversionと公開管理versionの分離を維持する。結果不明は照合し、別要求の上書きを防ぐ。

公開用blog/v1を起点に、イベントタグ・日時・復元時のID対応を含む正式形式を#394と定める。schema識別子で公開版→下書きを変換し、未知schema・別種別の履歴は拒否。直近3公開履歴＋復元前下書き1件を共通契約に従って保持。

URL所有権は正規化した公開パスをキーとする案。固定ページ、既存ブログ/イベント、新しい年別一覧、転送予約を含めて衝突検査。保存では予約せず、公開前チェックと原子的な予約の両方で並行公開の二重所有を防ぐ。既存eventの予約を移行で失わない。

旧nameのエンコードを台帳と照合し、二重エンコードを防ぐ。slug変更は旧URLから最新公開URLへ一段転送。公開停止と予約保持の規則は#390・#413の共通契約を確定して接続する。

## D1移行

追加migrationでCHECK・作成/複製トリガーを変更。更新typeは保存済みレコードを正とし、作成fingerprintにtypeを含める。既存eventのID・payload・version・操作結果・履歴・URL予約を保持。複製したローカルDBで件数・内容・旧操作IDの再送を前後照合してから稼働環境への適用を判断する。


## 編集snapshotと原本保全の関連（案）

記事所属の不変保全レコードをsourceRefで参照し、旧attrsを編集/公開APIへ自由入力させない。通常の下書き要求へ原本HTML・保全attrs一式を同梱しない。公開用ASTからsourceRefを外すため、サーバー側の公開履歴は対応する不変の編集snapshotとの関係を保持する。複製では新記事所属の参照をサーバーで再発行し、復元時は元属性を推測せず編集snapshotを使う。永続化と履歴削除時の参照保全は正式migration設計の対象。
