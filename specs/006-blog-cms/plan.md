# ブログCMSの設計案

対象 #418。ブランチ `codex/issue-418-blog-design`。分岐元・統合先 `version-4`。
入力は[合意済み要件](spec.md)。基本設計方針は利用者確認済み。本文はTiptapを第一候補として[互換性検証](tiptap-compatibility.md)を行い、採用条件を具体化中。独立試作と保存/公開契約の設計検証は実施済み。2026-11-16の利用者レビューで新規ブログの下書き保存→再編集までのCMS実装を承認。今回の本文はTiptapの新規テキスト・見出し・リスト・引用・リンクを対象とする。添付登録・旧記事取り込み・公開接続・本番配信は後続。

## 方針

イベントCMSの保存・競合検出・同じ操作の再送・複製・公開履歴を種別対応に拡張する。ブログ固有の入力・検証・公開候補変換・履歴表示は分ける。既存の公開用 `blog/v1` を下書き用に緩めず、未分類・途中入力を保持する形式を別に設ける。

汎用名でもevent固定の処理が残るため、画面だけでなく一覧・検索・件数の種別分離、D1制約・トリガー、ルート直下のURL所有権を扱う。保存だけでは公開版を変えず、配信確認前に公開成功としない。

## 技術的な前提

- リポジトリの宣言: Node 24.x、pnpm 10.28.2、TypeScript 6.0.3、React 19.2.7、MUI 9.5.0、Tailwind CSS 4.3.2、Vite 8.1.3。
- Workers・D1・Accessを継続利用。Astroへの正式データ接続は #394、配信方式は #413・#390。
- Vitest・PlaywrightとPC実操作で検証。画面は1440px・ライトモードを基準とする。
- 対象はブログ一覧・新規・編集・履歴と共通処理への影響。310件の旧スナップショットは照合資料であり、本番最新件数ではない。
- 新しい速度SLAは設けず、既存の1秒後自動保存・20件単位のCMS一覧を維持する案。公開サイトの一覧方式とは別。

## 変更する境界

| 対象 | 設計案 |
| --- | --- |
| `cms/src/app/routes.tsx`、`features/content/` | type、一覧/編集/履歴URL、初期値、固有フォームを明示的に渡し、event固定値を除く |
| `cms/src/features/blog/`（新規） | 下書き型・初期値、本文接続、カテゴリ・タグ・スイッチ、ブログ履歴表示 |
| `cms/worker/routes/contents.ts`、`repositories/content-drafts.ts` | type/schema別に検証。更新は保存済みtypeを使い、一覧・検索・件数を種別で絞る |
| `cms/migrations/` | 既存データを保つ追加migrationでCHECK・作成/複製トリガーを変更 |
| `cms/worker/services/restore.ts`、`publication.ts` | type/schema別変換と共通の版照合・再送・保護下書き・履歴保持 |
| `packages/content-schema/` | ブログ下書きと公開形式を区別。映画タグ→作品ID、イベントタグ、日時を明示 |
| URL予約・公開export・Astro | 固定ページ・旧転送元との衝突、正式snapshotと一覧への接続 |

種別登録はevent/blogに必要な差分に限る。他種別や汎用プラグイン機構は先回りして作らない。

## 原則・品質基準との照合

設計前後に原則・品質基準・開発ルール・CMS UIルールへ照合した。旧URL・本文・添付・公開日・分類を保ち、変換不能な情報を黙って落とさない。下書き・公開候補・確定版・保護枠を分離し、保存/復元では配信しない。Figma共通部品を使用し、本文未定の状態を画面完成としない。

公開ページのWCAG 2.2 AA、検索到達性、本文とメタ情報の一致は公開側で検証する。CMS保存の成功やAIの文書検査だけで受け入れ完了にしない。原則への例外は設けず、未解決の設計ゲートを明示する。
